# routers - camada HTTP do CRM (endpoints `/api/*` e paginas Jinja)

Cada arquivo declara um `APIRouter` com `prefix="/api/<recurso>"` e e registrado em `app/main.py`.
`pages.py` e a excecao: serve HTML via `Jinja2Templates(directory="templates")`, sem prefixo e com
`include_in_schema=False`. Camada sensivel a seguranca - e aqui que auth e autorizacao sao decididas.

## Responsibility

Traduzir HTTP em chamada de dominio: validar entrada via schema Pydantic, resolver dependencias
(`Depends(get_db)`, `Depends(get_current_user)`, `Depends(require_admin)`) e devolver `HTTPException`
com status correto. Modelagem de dados NAO mora aqui (`app/models/`), forma do payload NAO mora aqui
(`app/schemas/`), e regra de negocio do modulo operacional NAO mora aqui (`app/services/`). Query SQL
crua para a IA fica em `app/services/ai_tools.py`, nao em rota.

## Key patterns

- Rotas do modulo `operational_*` sao finas: instanciam o service (`OperationalCardService(db)`), chamam
  um metodo e mapeiam `ValueError` para `HTTP_404_NOT_FOUND` e `Exception` para 500 com mensagem generica.
- Rotas legadas (`leads.py`, `pipeline.py`, `tags.py`, `teams.py`, `users.py`, `tasks.py`, `segments.py`)
  falam com a `Session` direto e chamam `db.commit()` na propria rota. Padrao aceito - siga o do arquivo.
- Autorizacao e por rota, nunca global: `Depends(get_current_user)` para leitura, `Depends(require_admin)`
  para mutacao/administracao. Paginas usam `require_page_session(request, db)` + `page_login_redirect`.
- Paginacao profunda usa cursor keyset com `_cursor_encode`/`_cursor_decode` sobre `(created_at, id)`
  (`leads.py`) ou `(updated_at, id)` (`pipeline.py`). Cursor corrompido vira 400, nunca 500.
- Query com funcao especifica de banco ramifica em `IS_SQLITE` (`from app.database import IS_SQLITE`) -
  dev roda SQLite, producao roda PostgreSQL, e os dois precisam passar.
- Carga de relacionamento e explicita (`joinedload`, `selectinload`) para nao gerar N+1;
  `tests/test_perf_query_count.py` guarda isso.

  tamanho e tipo (`MAX_UPLOAD_SIZE_BYTES`).

  `app/services/`, nao para dentro do handler.

## Local conventions

- Todo endpoint novo de mutacao passa por `require_admin` a menos que exista razao escrita em comentario.
  `tests/test_security_greps.py` falha se a contagem total de `require_admin` cair.
- Arquivo de rota importa schemas de `app.schemas.<recurso>` e nunca devolve o model SQLAlchemy direto.
- Comentarios de decisao levam o codigo do WP (`WP-SEC-03`, `DATA-01`) e explicam o porque, nao o que.
- `leads.py` e `pipeline.py` ja passam de 780 linhas: acrescente no arquivo existente em vez de
  reorganizar, e proponha extracao so quando for o objetivo da tarefa.
