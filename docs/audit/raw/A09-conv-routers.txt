AGENT NOTES:
- Endpoint inventory: all deps are get_current_user unless marked. ADMIN routes: templates service-availability GET/PUT, param-map PUT; variables POST/PUT/DELETE; api_config PUT/test/connect/disconnect. NO-AUTH routes: POST /api/auth/login, GET /api/auth/me (always 500), GET /api/auth/me/validate (always 200). pages.py gates on cookie PRESENCE only.
- Inbox filters (conversations.py:194-214; aberta = status IN (aberta,aguardando); humana = is_bot_active IS FALSE): bia = aberta+bot; fila = aberta+humana+atendente IS NULL; meus = aberta+humana+atendente==me; todos = aberta+humana; encerradas = status==encerrada. Open conversations are partitioned EXACTLY by bia + todos (no gap, no overlap); meus and fila are strict subsets of todos so badges intentionally double-count. Ordering: fila = queued_at ASC NULLS LAST, id ASC; others = updated_at DESC, id DESC.
- There is NO per-conversation ownership model anywhere: every authenticated principal can read, tag, note, close, reassign, release and send in any conversation. /claim advertises a lock that /release, PUT /{id} and POST /{id}/messages do not honour.
NOT VERIFIED: whether unread_count = 0 on an already-zero row emits a real UPDATE (and bumps updated_at) on every 5s poll; runtime behaviour of func.count().filter() on the deployed PostgreSQL; actual production ENVIRONMENT/CONVERSAS_SEED_DEV_DATA values.
