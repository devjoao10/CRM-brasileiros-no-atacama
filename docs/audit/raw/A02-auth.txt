AGENT NOTES: get_current_user has four mechanisms in priority order (internal HMAC > X-API-Key > Bearer > cookie) and EVERY branch raises on failure rather than falling through - one structural fix, not four patches. AUTH-LOOP-01 unified /hub and /api/auth/me on _get_user_from_jwt and is well tested; the API path is the remaining unmerged half. conversas has a hardcoded fallback SECRET_KEY = os.getenv("SECRET_KEY","dev-secret-key-change-me") while the CRM fails fast, and the compose entry for conversas uses plain ${SECRET_KEY} without the :? guard. oauth2_scheme points at a JSON endpoint so the Swagger Authorize button cannot work (dev only). The role claim is embedded in the JWT but no code reads it for authorization - correct, but a trap. UserCreate.password has min_length=6, no complexity rule, no lockout. The email_verified login gate is commented out while user creation hardcodes email_verified=True - consistently disabled, not half-broken. No CSP header is set; given the token lives in localStorage a CSP is the highest-value missing mitigation.
