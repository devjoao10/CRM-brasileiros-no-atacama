# migrations - reconciliacao manual e idempotente de schema

Scripts `mNNN_*.py` para bancos JA existentes, enquanto o projeto nao adota Alembic (WP-DATA-02).
Bancos novos nascem completos via `Base.metadata.create_all()` a partir dos models.

## Responsibility

Aplicar mudanca de schema em banco existente, de forma controlada e fora do startup do app. Nao roda no
`lifespan` (`app/main.py` deixou de fazer `ALTER TABLE` no DATA-01), nao cria banco novo e nao contem
regra de negocio. Rodar em producao e acao humana, nunca de agente.

## Key patterns

- Cada script expoe `run(engine=None)` e e executavel direto: `python migrations/mNNN_*.py`.
- Idempotencia e obrigatoria: inspecione antes de agir (`inspect(engine).get_table_names()`,
  checagem de coluna) e acumule o que foi feito em `actions`.
- Compatibilidade dupla SQLite (dev) e PostgreSQL (prod) - o mesmo script roda nos dois.
- Migration do Conversas insere `conversas/` no `sys.path` e importa `app.config`/`app.models` de la;
  por isso roda em processo proprio, separado do CRM.
- Mudanca aditiva e nullable, para que o rollback seja "deixar a coluna sem uso" em vez de `DROP COLUMN`.
- Ordem importa quando ha FK (m003 -> m004 -> m005); o cabecalho do script declara a dependencia.

## Local conventions

- Numeracao sequencial `mNNN_<escopo>_<assunto>.py`, nunca reutilizada.
- Docstring do topo declara: work package, o que muda, ordem de aplicacao e o gate de producao.
- Script novo entra tambem na tabela de `migrations/README.md`.
- Rodar `python -m migrations.mNNN_...` local antes de propor aplicacao em staging.
