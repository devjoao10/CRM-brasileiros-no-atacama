# schemas - contratos Pydantic do Conversas

Schemas de entrada e saida do inbox: mensagens, conversas, notas, templates, variaveis, quick replies e
configuracao de API.

## Responsibility

Validar formato e tamanho do que entra pelas rotas do Conversas e definir o formato do que sai. Nao
valida regra que depende de estado externo - aridade de parametro de template, por exemplo, e conferida
no backend contra os `components` reais da Meta, nao aqui. Persistencia fica em `app/models/`.

## Key patterns

- `MessageCreate` limita `content` com `Field(..., min_length=1, max_length=5000)` - o mesmo teto vale
  para `NoteCreate`.
- Identidade de template na Meta e o par `(name, language)`: `template_language` tem default `pt_BR`
  para preservar chamadas antigas que so mandavam o nome.
- `template_params` e lista posicional correspondente a `{{1}}, {{2}}, ...`; a ordem e o contrato.
- Campos derivados para a UI (`user_nome`) entram como `Optional[...]` no `*Response`, preenchidos pela rota.
- Comentario acima do campo explica a decisao e cita o work package, nao o tipo.

## Applied rules

Rules active in this directory - read them before touching code here:

- @.claude/rules/fastapi/coding-standards.md - toda rota devolve `response_model` definido aqui; nunca o
  model SQLAlchemy direto.
- @.claude/rules/ecc/python/fastapi.md - Pydantic v2, `Field` com limites explicitos nas entradas.
- @.claude/rules/06-security.md - `*Response` nao expoe token da Meta, hash de senha nem id interno da
  Meta sem necessidade.

## Local conventions

- Nota interna e um tipo proprio (`NoteCreate`) justamente porque NUNCA vai para o WhatsApp - nao a
  unifique com `MessageCreate`.
- Limite de tamanho novo deve bater com o limite aplicado em `services/media_policy.py` quando o campo
  descrever midia.
